# AutoClip Studio optimization audit

November 25, 2026

Keep the existing PySide6 application, sequential job queue, and native Windows source and OneDir workflows. Preserve local and YouTube import, optional AI providers and no-key scoring, Whisper word timestamps, face tracking, caption templates, clip preview, MP4 output, and existing project data. Apply the work in small changes with the CPU paths available throughout.

## Baseline from this checkout

- All 8 unit tests passed on Windows with Python 3.12.16 and PySide6 6.8.3.
- The media smoke test produced a valid 6.30-second MP4 with tracking and burned-in ASS captions on the RTX 3050 Laptop GPU through FFmpeg 9.1. The same fixture passed through libx264 when the NVENC capability check was forced off for that run. These two small runs establish functionality. A timing comparison needs representative fixtures and repeated runs.
- The bundled FFmpeg advertises NVENC, AMF, and QSV. NVENC was exercised. CTranslate2 4.9.1 reported CUDA float16 support. Actual CUDA transcription, AMF/QSV rendering, and recovery from an NVENC runtime failure remain unverified.
- All six pages constructed in Qt offscreen mode at a 1.5 scale factor. At a 1,000 × 680 window size, the Dashboard reported a 1,657-pixel minimum width hint for a 780-pixel content area. The source contains a long, non-wrapping Dashboard label. Native Windows visual and assistive-technology checks, full speech transcription, live provider and YouTube calls, and the packaged application remain outside this baseline.
- Local reproduction confirmed that a valid top-level provider JSON array raises `AttributeError`, and that two distinct accepted YouTube `/live/` links both resolve to the same generic download basename. No downloads were made for that check.

## Implementation and verification

- Implemented cooperative cancellation around provider analysis, upload reads and polling. Active sockets and native inference can still wait for the underlying call to return. Added separate download and transcript cache identities, job-scoped uncached downloads, validated clip publication, atomic manifest writes, and job artifact cleanup.
- Reduced the desktop minimum window to 760 × 560 and improved keyboard focus, progress display, and clip selection. All six pages fit the minimum width in Qt offscreen tests at 100%, 125%, and 150% scale. The native OneDir smoke completed a three-clip project and exited normally. A second run closed during FFmpeg rendering, terminated its owned FFmpeg process within the five-second test limit, and recorded a cancelled project.
- Reused source dimensions per job, tested NVENC at runtime, bounded retained subprocess logs, and used structured FFmpeg progress. A 241-sample crop expression for a 180-second clip failed the old FFmpeg expression parser path and passed with balanced interpolation. A rotated, variable-frame-rate, silent source rendered successfully through libx264 from paths containing spaces and Unicode.
- The 16-test suite passed. Controlled tests exercised provider cancellation and Gemini file deletion, distinct cache identities, and NVENC-to-libx264 recovery with a staged export. Both source and packaged downloader executables successfully transferred a local HTTP fixture. Live AI providers, YouTube extraction, AMF, QSV and Windows Narrator were outside this verification.
- The Windows x64 OneDir build measured 812.1 MiB. The pinned FFmpeg 9.1 ZIP matched the published SHA-256, and the required executables were present in the archive. The build and application tests used disposable locations without reinstalling the source environment or the Windows installer.

### Windows measurements

The 83-second 720p speech fixture generated three 720 × 1280 clips with tracking and captions on an RTX 3050 Laptop GPU. CPU transcription used Faster-Whisper tiny. The initial measured run had local model weights and no transcript cache. Peaks are sampled Windows working sets and in-progress file sizes. These are single-machine observations.

| Run | Wall time | App peak | Child-process peak | Temporary working files |
| --- | ---: | ---: | ---: | ---: |
| Fresh transcript | 19.87 s | 329.6 MiB | 288.6 MiB | 6.0 MiB |
| Transcript cache hit, two runs | 6.95–7.12 s | 332.5–332.9 MiB | 288.4–288.5 MiB | 5.8–6.0 MiB |

On a separate synthetic transcript of 8,000 segments, local highlight scoring returned the same nine results. Median time across five runs per implementation went from 3.513 s to 0.334 s by removing repeated tail copies and stopping deduplication once enough candidates were accepted. This measures the selector alone.

Two CPU Whisper runs with cached weights spent 0.21–0.64 s constructing the model and 6.23–6.78 s decoding and transcribing. That cost did not justify retaining a resident model for this fixture. Forward tracking decode matched 96 of 96 sampled frames on the constant-frame-rate fixture and took 0.89 s versus 4.11 s for repeated seeks. The application retains its current sampling to preserve behavior across variable frame rates and codecs until broader parity is established.

An actual CUDA transcription attempt found that `cublas64_12.dll` could not load. CPU fallback completed with 20 transcript segments. Broader GPU comparisons need the corresponding runtime libraries and hardware. NVENC was verified independently and used in the successful native desktop run.
